# PDF Flow UI 重构验收

本地生产构建验收；使用非个人 A/B 六页、A/B 八页及 C 七十页样例。全部文件处理仍在浏览器本地完成。本轮没有发布线上版本。

## 完成的改造

- 补齐网站导航、空态、上传区、工作区和页脚样式，采用白/浅灰、精确字号和低装饰层级。
- 恢复蓝绿色品牌色，统一主按钮、焦点、选中、禁用及错误状态。
- 新增共享 PdfUploadArea，保留现有文件输入和处理函数；显示读取状态，不展示固定0%假进度。
- 分割采用文件信息行、文档画布与规则面板；明确预计分组只筛选预览，编辑选择与输出选择保持独立。
- 合并采用来源列表和顺序画布；缩略图移除多层彩色底栏，保留选择、预览、鼠标/键盘/触屏传感器和指定页移动。
- 手机编辑工具条压缩到两行，命中区域不随视觉勾选缩小。移动面板保留焦点管理与Escape返回。
- 修复React与Tailwind在899px宽度的模式不一致，统一为width < 900px。
- 600px高桌面窗口收紧合并面板最大高度，82页场景生成按钮底部551.19px，首屏可达。

## 自动化检查

- npm run build：TypeScript、Vite与PWA构建通过。仍有原有的大体积JS chunk提示，未进行打包架构调整。
- npm test：11个文件、70项测试通过。
- git diff --check：通过。
- Chromium + axe-core：检查过分割、合并与移动顺序面板，0项confirmed violations；部分对比度项目因重叠/伪元素/短文本返回incomplete，不能宣称全站WCAG认证。
- 手工计算设计token对比度：#6E6E73 / #F5F5F7 = 4.66:1；#6E6E73 / 白色 = 5.07:1；白色 / #0E7490 = 5.36:1；#1D1D1F / #F5F5F7 = 15.46:1。这不是所有组合及状态的逐像素审计。

## 覆盖边界

使用桌面Chromium的窗口尺寸模拟手机和平板，未做真实iPhone/Safari、系统分享、剪贴板权限及PWA安装验收。现有单元测试覆盖历史增删/保留期、文件替换/移除隔离、非法页码与损坏输入等；不是这些路径的全部真实设备验收。未验证超大、加密、真实云盘占位文件与屏幕阅读器实机。不修改PDF Worker、历史数据结构或文件处理协议。
